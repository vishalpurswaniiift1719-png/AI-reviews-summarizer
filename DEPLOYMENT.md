# Deployment Guide

This document outlines the end-to-end deployment architecture for the **AI Reviews Summarizer**, which consists of three decoupled components:
1. **Frontend Dashboard** (Hosted on Vercel)
2. **AI Generation Pipeline** (Cron Job / Worker)
3. **Google Workspace MCP Server** (Hosted on Railway)

---

## 1. Frontend Dashboard (Vercel)

The dashboard is a static frontend that visualizes the `latest_pulse.json` generated by the AI Pipeline and provides strict, authenticated gateways to the MCP Google Workspace tools.

### Deployment Steps
1. Log in to [Vercel](https://vercel.com/) and click **Add New Project**.
2. Import the `AI-reviews-summarizer` GitHub repository.
3. **Configure Project Settings**:
   - **Root Directory**: Set this to `dashboard` (Important: Vercel must serve out of the `dashboard` folder, not the repository root).
   - **Framework Preset**: Other (Static HTML).
   - **Build Command**: Leave empty.
   - **Output Directory**: Leave empty (or `.` ).
4. Click **Deploy**.

### Post-Deployment Security (Google Sign-In)
For the explicit authorization gatekeeper to work, Google must trust your new Vercel domain.
1. Go to your [Google Cloud Console Credentials Page](https://console.cloud.google.com/apis/credentials).
2. Edit the **Web application** OAuth 2.0 Client ID (the one matching `49695217356-iiigbht3adaailg05md9g2nrr8g077oc...`).
3. Under **Authorized JavaScript origins**, click **+ ADD URI** and paste your exact Vercel URL (e.g., `https://my-noon-dashboard.vercel.app`).
4. Click **Save**.

## 2. Google Workspace MCP Server (Railway)

The MCP Server is an independent, secure bridge that executes Google Docs and Gmail API calls on behalf of the AI pipeline. It uses Server-Sent Events (SSE) and token-based authentication.

### Deployment Steps
1. Log in to [Railway](https://railway.app/) and create a **New Project** -> **Deploy from GitHub repo**.
2. Select the `AI Summarizer MCP server` repository.
3. Navigate to the **Variables** tab in Railway and configure the environment:
   ```env
   PORT=3000
   MCP_AUTH_TOKEN=super_secret_token_123   # Must match the token used by the AI pipeline
   
   # Google OAuth Credentials (generated via generate_token.mjs)
   GOOGLE_CLIENT_ID=your_client_id
   GOOGLE_CLIENT_SECRET=your_client_secret
   GOOGLE_REFRESH_TOKEN=your_refresh_token
   ```
4. Railway will automatically detect the Node.js environment, install dependencies, and run the server.
5. In the **Settings** tab under **Networking**, generate a Public Domain. This is your `MCP_SERVER_SSE_URL` (e.g., `https://your-mcp-server.up.railway.app/sse`).

## 3. AI Generation Pipeline (Cron Job / Worker)

The AI Pipeline is the Python backend that reads Play Store reviews, processes them with Gemini, saves the `latest_pulse.json` for the frontend, and triggers the MCP server.

### Deployment Options
Because the pipeline is a batch process rather than an active web server, it should be deployed as a **Scheduled Cron Job**. You can deploy this on Railway, Render, GitHub Actions, or AWS EventBridge/Lambda.

### Environment Variables (`.env`)
Regardless of where you host the Python script, it requires the following environment variables:
```env
# AI Models
GEMINI_API_KEY=your_gemini_key

# App Configuration
GOOGLE_PLAY_APP_ID=com.noon.buyerapp
REVIEW_WEEKS=10

# Security & Access
AUTHORIZED_VIEWERS=vishalpurswani.iift1719@gmail.com,another.exec@noon.com

# MCP Integration (from Railway deployment)
MCP_SERVER_SSE_URL=https://your-mcp-server.up.railway.app/sse
MCP_AUTH_TOKEN=super_secret_token_123
TARGET_GOOGLE_DOC_ID=your_google_doc_id

# Email Dispatch
EMAIL_RECIPIENT=vishalpurswani2006@gmail.com
```

### Running the Job
To execute the pipeline, the server or cron scheduler simply needs to run:
```bash
pip install -r requirements.txt
python src/main.py
```

*Note: The generated `dashboard/data/latest_pulse.json` and `mcp_sync.json` files must be served to the Vercel frontend. If you run the Python script on a separate server, you will need to add a final step in `main.py` (or a shell script) to commit and push those JSON files back to the GitHub repository so Vercel can automatically redeploy and serve the fresh data.*
